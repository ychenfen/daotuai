# 路线图（2026-11-01 制定）

依据：第 1 集真实全片（12 镜 × 5 秒，万相 3.0 480P，出片 18 元，项目累计约 21 元）的质检结果——10 合格、1 待看、1 不合格，
问题几乎都是“分镜里写的关键动作没演出来”；配音暴露过镜头时长装不下台词（已修）。工作台已部署到 `https://stock.yuchenxu.cn/studio/`。

## 第一阶段：质量闭环（云端开发，全部模拟测试，不花钱）

| # | 项 | 状态 |
|---|---|---|
| 1 | 按质检意见重抽：质检问题 / 审片打回原因写回提示词再出一版；新版本记着来源和改动；分数更低自动保留原版本；可选“不合格自动重抽”（每镜 ≤1~3 次，受预算约束） | ✅ 2026-11-01 |
| 2 | 动作密度：分镜规则“每段 ≥2 秒、一个主动作、5 秒卡最多 2 段、最多两人对话”；塞太满的卡标黄，一键拆成两张 | ✅ 2026-11-01 |
| 3 | 审片：每个版本 通过 / 打回（写原因）；成片页显示通过/打回/未审 | ✅ 2026-11-01（含“剪辑”页逐镜审片） |
| 4 | 剪辑精修：每镜入点/出点、转场（硬切/叠化），配音和字幕跟着偏移；剪辑工程按入点导出 | ✅ 2026-11-01 |

## 第二阶段：服务器当主站（需要电脑在线一次）

| # | 项 | 说明 / 状态 |
|---|---|---|
| 5 | 生产只在服务器上做，电脑版只做备份；电脑上的最新数据再同步一次 | 避免两份数据分叉 |
| 6 | 服务器自动更新：每 10 分钟拉 GitHub → 测试全过才替换 → 起不来自动回滚 | ✅ 脚本已写好并在沙盒验证 4 条路径；需电脑在线部署一次 + 在 GitHub 加只读部署公钥 |
| 7 | LibTV 登录回调改到服务器地址 | ✅ 经工作台转发；部署时写入回跳地址 |
| 8 | 磁盘与备份：旧版本视频清理、每日备份 | ✅ 首页“存储与运行状态”一键清理；每日 04:30 备份数据库留 14 天 |
